## Anatomy

```tsx
import { useState } from 'react';
import { Calendar } from '@package/ui/calendar';

export function Example() {
  const [date, setDate] = useState<Date | undefined>(new Date());

  return (
    <Calendar
      value={date}
      onValueChange={setDate}
    />
  );
}
```

## Range mode

`mode="range"` renders a continuous span instead of a single day. The calendar stays presentational:
it reports day presses through `onSelect` and pointer movement through `onHoverChange`, and marks each
day with `data-range="start" | "middle" | "end"`. Anchor, preview, and bound handling live in the
shared `useRangeSelection` hook from `@package/ui/use-range-selection`, which is also what
`DateRangePicker` is built on.

```tsx
import { Calendar } from '@package/ui/calendar';
import { useRangeSelection } from '@package/ui/use-range-selection';

export function Example() {
  const selection = useRangeSelection({ onSelect: (range) => console.log(range) });

  return (
    <Calendar
      mode="range"
      selected={selection.selected}
      preview={selection.preview}
      anchor={selection.anchor}
      onSelect={selection.press}
      onHoverChange={selection.hover}
    />
  );
}
```

Reach for `DateRangePicker` when a formatted trigger and popover are wanted; use the calendar directly
when the grid is the layout.

## Localization

Labels are formatted with `Intl.DateTimeFormat`, so the component stays zero-dependency. The heading,
weekday names, and each day's screen-reader label follow the runtime locale by default; the `locale`
prop pins one instead:

```tsx
<Calendar
  value={date}
  onValueChange={setDate}
  locale="fr-FR"
/>
```

Only the names localize. The grid stays Sunday-first, with day columns indexed by `getDay()`, so the
week layout does not shift between locales. `DatePicker` and `DateRangePicker` forward the same prop to
their trigger text and their calendar.
