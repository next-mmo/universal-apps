In addition to React Native Web (`apps/native-playground`) and Bare React Native (`apps/uniwind-bare`), the same Apple-inspired design system powers **Expo** mobile applications running on Android and iOS devices. Expo bundles through **Metro** via `@expo/metro-config` and compiles Tailwind CSS v4 utilities for native view trees using **Uniwind**.

## Architecture comparison

| Layer | React Native Web (RNW) | Bare React Native | Expo (Mobile) |
| ----- | ---------------------- | ----------------- | ------------- |
| Bundler | Vite (`vite-plugin-rnw`, `uniwind/vite`) | Metro (`@react-native/metro-config`, `uniwind/metro`) | Metro (`@expo/metro-config`, `uniwind/metro`) |
| Runtime | Browser DOM (simulated primitives) | Native Android & iOS view hierarchies | Expo Android & iOS client and standalone runtimes |
| Tokens | `@package/ui/tokens.css` (CSS variables) | Same `@package/ui/tokens.css`, compiled at build time | Same `@package/ui/tokens.css`, compiled at build time |
| Components | `@package/ui-native` (`Pressable`, `View`, `Text`) | Same `@package/ui-native` primitives | Same `@package/ui-native` primitives |
| Scaffolding | `universal create <name> --framework native` | `universal create <name> --framework uniwind-bare` | `universal create <name> --framework expo-uniwind` |

## Scaffolding a new Expo project

Create a runnable Expo project configured with Metro, Uniwind, and Tailwind CSS v4:

```bash
npx @next-mmo/universal-cli create my-mobile-app --framework expo-uniwind
```

Or using the alias:

```bash
npx @next-mmo/universal-cli create my-mobile-app --framework expo
```

This scaffolds:
- `metro.config.js` configured with `@expo/metro-config` and `withUniwindConfig`
- `babel.config.js` with `babel-preset-expo`
- `app.json` preconfigured with `newArchEnabled: true`
- `src/index.css` importing Tailwind v4, Uniwind, and design system tokens
- `index.js` registering the root component via `registerRootComponent` from `expo`
- `src/App.tsx` rendering styled native components
- `src/uniwind-env.d.ts` configuring Uniwind TypeScript bindings
- `universal.json` pre-configured to add `@package/ui-native` components

## Metro bundler configuration

In an Expo project, Uniwind integrates seamlessly with Expo's Metro bundler configuration:

```js
// metro.config.js
const { getDefaultConfig } = require('expo/metro-config');
const { withUniwindConfig } = require('uniwind/metro');

const config = getDefaultConfig(__dirname);

module.exports = withUniwindConfig(config, {
  cssEntryFile: './src/index.css',
});
```

Uniwind resolves Tailwind utility classes during bundling and produces optimized native style objects.

## CSS entry and design tokens

The CSS entry file (`src/index.css`) imports Tailwind v4, Uniwind, and the shared design tokens:

```css
@import "tailwindcss";
@import "uniwind";
@import "@package/ui/src/styles/tokens.css";
```

In source-distributed projects (via `universal init` and `universal add`), the token file is generated locally under `src/lib/universal/ui/styles/tokens.css`.

## Component parity on Expo

Components in `@package/ui-native` (and source-distributed components) are crafted strictly from standard React Native primitives:

- **Buttons & Pressables**: Built with React Native's `Pressable` and `Text`, with pressed state feedback using `active:` opacity utilities.
- **Form Controls**: `Input` wraps `TextInput` with token-aware placeholders; `Switch` provides a pure native toggle.
- **Overlay Sheets**: Because native has no DOM portals, overlay components (`Dialog`, `DropdownMenu`, `Popover`, `Select`) render using React Native's `Modal` component over dimmed backdrops.
- **Animations**: `Skeleton` uses React Native `Animated` loops instead of CSS keyframes.
- **Icons**: Simple glyphs (✓, ⌄, ×) are used to avoid hard dependencies on native SVG packages.

## Theme and dark mode

Theme transitions are managed directly through Uniwind:

```tsx
import { Uniwind } from 'uniwind';

// Toggle between light and dark modes
Uniwind.setTheme('dark');
Uniwind.setTheme('light');
```

Uniwind dynamically switches CSS custom properties and re-renders affected native components without reloading the bundle.
